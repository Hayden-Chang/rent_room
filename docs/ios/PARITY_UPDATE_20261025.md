## 本批组件边界

新增 `InspectionSetupSurface`、`InspectionTemplateEditor`、`InspectionModeChoice` 和 `XiaodaGreeting`。文案、顺序、模式示例和配色取自上述小程序快照的 welcome/template-editor/guidance 源码。小搭直接复用 `assets/xiaoda/greet.png`，SHA-256 `e30795a399a85139e5090cf9119f571b8d7cd35b567223c9213f99852c305929`。

只在 DEBUG 显式 `--component-review inspection-setup` 入口加载。普通启动和 Release 继续使用既有 AppRoot；组件使用内存草稿，不创建房源，不更改模板，不请求登录或发放容量。初次精简默认值属于评审宿主，旧用户详细模式迁移尚未实施。

拖动柄位于左侧，采用 iOS 原生拖放，放下时更新顺序；停用行保留并可恢复。VoiceOver 提供上移/下移操作。该组件尚未复制小程序的实时行位移和边缘自动滚动；拖放反馈需列入本次视觉确认，不能宣称手势逐帧一致。

验证映射：`InspectionSetupTests` 覆盖停用/恢复、最后一项保护、双向移动、非法外部内容、值草稿隔离、图片解码和显式评审入口；`InspectionSetupReviewTests` 通过真实按钮和原生拖动验证排序、往返及模式互斥。截图仅证明组件，不能证明房源持久化、引导完整流程或全功能对齐。

后续接入顺序：组件批准 → 同源清单/模板/小搭桥接及持久化 → 房源页面接线与回归 → 容量协议和平台能力 → 最终 PR head 验证及真机验收。所有条目完成前，PR 保持 Draft，不能标记“已实现所有功能”。
