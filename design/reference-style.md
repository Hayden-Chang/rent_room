# 看房产品 UI 风格参考

整理日期：2026-10-10。

参考对象：用户提供录屏中的「小坡岛」租房小程序。

来源：`/Users/pc/Downloads/ScreenRecording_10-10-2026 14-17-10_1.MP4`，时长约 53 秒。已查看首页、房源列表、发布入口与表单、房源详情、收藏、个人页和地图页面的关键帧。

本文用于后续界面设计与评审。**“观察”描述录屏中可见的表现；“建议”是针对本项目的设计转化，不代表参考产品的原始设计参数。** 具体色值、尺寸、字体和动效时长未从源码验证。

## 1. 风格定位

**蓝紫强调色 + 灰白背景 + 白色圆角卡片 + 照片优先 + 紧凑的信息层级 + 固定主操作。**

整体明亮、清爽，具有生活服务产品的实用感。页面通过图片、文字轻重、留白和少量色彩建立层次。精致感主要来自组件一致性：搜索框、筛选胶囊、图片角标、图标和按钮使用统一的视觉语言。

## 2. 录屏中的视觉规则

| 维度 | 观察 | 可复用规则 |
| --- | --- | --- |
| 主色 | 偏蓝的高饱和蓝紫色用于主按钮、价格、链接和选中状态 | 主色集中表达重点与可操作性 |
| 背景 | 页面主体接近灰白；首页顶部带有很浅的冷蓝色过渡 | 背景保持安静，用白色内容区形成轻微层次 |
| 文字 | 标题深黑加粗，说明和元信息为灰色，价格用蓝色突出 | 每个区域优先突出一个核心信息 |

| 图片 | 房源列表采用双列大图；详情页使用宽幅房间照片 | 图片先建立印象，文字补充判断信息 |
| 标签 | 浅蓝紫底的小胶囊；认证角标覆盖在图片上 | 标签短小，贴近对应对象，避免抢过标题 |

| 重点入口 | “发布房源”使用蓝色渐变、装饰形状和较明显的阴影 | 渐变与强阴影集中用于少数重要入口 |

## 3. 页面与组件组织

### 首页

观察到的顺序为：位置入口 → 快捷功能 → 搜索与主操作 → 推荐标题 → 快捷筛选 → 条件筛选 → 房源列表。

- 快捷功能采用统一的圆角图标底座和下方短标题。
- 搜索与找房操作集中在一张白色卡片内。
- “查看房源”作为主要动作，“去地图找”作为次要动作。
- 筛选分为可直接点击的胶囊和可展开的条件入口。

借鉴重点：把常用入口放在容易扫描的位置，确保用户能快速进入主要流程。具体入口数量应由本项目任务决定。

### 房源列表

- 双列布局中，照片占主要面积。
- 图片上放置认证和位置等轻量信息。
- 图片下方依次呈现名称、简短标签与价格。
- 价格使用主色，单位与说明采用较弱的文字样式。

借鉴重点：保持每张卡片字段顺序一致，让用户可以连续比较房源。

### 房源详情

- 按概况、可选房型、周边配套等内容分组。
- 房型卡片采用“宽幅照片 → 标题 → 设施摘要 → 价格与查看入口”的顺序。
- 周边信息通过类别图标、名称和距离建立层次。
- 底部固定显示价格、收藏和联系按钮。

借鉴重点：长页面仍保留核心操作，内容区需要为固定底栏预留足够空间。

### 发布与表单

- 发布入口突出一个主要行动。
- 表单使用标签与输入区域对齐的行式布局。
- 图片上传使用可识别的占位入口。
- 提示说明弱化显示，提交按钮固定在底部。

借鉴重点：字段分组清晰，必填、选填和错误状态可辨认；辅助说明保持可读。

### 地图

- 地图占据主体，上方悬浮搜索框和筛选面板。
- 地点通过带文字的标记展示。
- 底部使用独立胶囊按钮切换到列表。

借鉴重点：地图与列表作为同一批房源的两种查看方式，切换时应保留筛选条件。

## 4. 本项目的建议规范

以下是后续实现的起始建议，需通过实际页面验证。它们不是从录屏精确测量得到的参数，也不表示已在代码中应用。

### 配色角色

| 角色 | 建议表现 | 使用范围 |
| --- | --- | --- |
| 主色 | 鲜明、偏蓝的蓝紫色 | 主操作、链接、选中项、关键数字 |
| 主色浅底 | 很浅的蓝紫色 | 筛选选中背景、信息标签、轻量强调 |
| 页面背景 | 接近白色的冷灰 | 页面底层 |
| 内容表面 | 白色 | 卡片、表单区域、底栏 |
| 主文字 | 接近黑色的深灰 | 标题、主要内容 |
| 次文字 | 具有足够对比度的中灰 | 单位、时间、位置、辅助说明 |
| 分隔线 | 浅灰 | 行分隔、卡片细边框 |
| 业务状态色 | 与主色职责区分，辅以文字和图标 | 检查结果、问题提示、错误反馈 |

### 排版与间距

- 采用清晰的系统无衬线字体，中文、英文和数字的层级保持一致。
- 标题通过字号和字重突出；正文保持可读；辅助文字减少视觉重量但不牺牲对比度。
- 租金数值与单位分层，数值突出，单位紧邻。
- 使用统一的间距档位，页面边距、卡片内边距和列表间距保持规律。
- 卡片使用适中的圆角；筛选项与短标签使用胶囊形状。
- 同一页面避免叠加多层阴影，普通内容卡片优先使用留白与轻边框分组。

### 房源列表与详情

- 房源列表优先呈现照片、名称、租金；看房时间和检查进度作为辅助信息。
- 信息密度较高、需要比较检查结果时，可使用单列卡片，保证关键内容可读。
- 详情按房源概况、检查记录和照片分组。
- 固定底栏放置当前阶段最重要的动作，例如“开始检查”或“继续检查”；根据页面状态确定文案。

### 检查项、备注与照片

- 检查页面沿用浅灰底、白色分组和清晰标题。
- 检查项采用紧凑行式布局，优先显示名称与状态。
- 备注默认呈现短摘要，较长内容按需展开。
- 照片以小缩略图承载，更多图片通过数量提示进入查看。
- 添加备注、添加照片等次操作在需要时展开，控制首屏复杂度。
- “待检查”“已检查·无问题”“已检查·有问题”必须明确区分。
- 蓝色表示操作或选中；业务结果使用文字、图标及适当状态色共同表达。

### 交互一致性

- 常用筛选直接可达，复杂条件集中展开。
- 列表与详情往返时尽量保留滚动位置和筛选状态。
- 固定操作区不遮挡正文，并考虑底部安全区与键盘。
- 核心页面切换优先响应本地状态，网络加载在页面内提供明确反馈。
- 录屏关键帧不足以确定精确动效曲线与响应耗时；这些需要后续实际运行验证。

## 5. 需要改进后再借鉴的地方

- **辅助文字偏小、偏浅：** 本项目应优先保证说明、状态和单位的可读性。
- **悬浮按钮遮挡内容：** 录屏中的部分按钮覆盖照片或卡片；本项目优先为操作预留独立空间。
- **地图标记重叠：** 地点密集时需要聚合、按缩放级别显示或突出选中对象。
- **首页入口较多：** 看房记录产品应按自己的主要任务组织入口，控制首屏负担。
- **加载与空白状态：** 录屏出现骨架和空白页面片段，仅凭关键帧无法判断原因与完整等待过程；实现时应提供加载、空数据和失败反馈。

## 6. 后续设计评审要点

- 主色、圆角、图标和间距是否一致？
- 每个区域的标题、主要内容和辅助信息是否容易区分？
- 照片、租金与检查状态是否便于快速扫描？
- 检查项是否紧凑，备注与照片是否容易展开？
- 未检查与已检查有问题是否清楚区分？
- 固定操作区和悬浮控件是否遮挡内容？
- 小屏幕、长标题和大字体下是否仍然可读？
- 页面切换、返回和地图列表切换是否保持必要状态？

本文记录设计方向；最终界面效果与交互体验需通过实际渲染和操作验证。
